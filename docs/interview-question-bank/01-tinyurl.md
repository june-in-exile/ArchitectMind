# Q1 — 短網址服務 TinyURL

**難度：** 入門
**建議時間：** 20 分鐘

## 情境

設計一個公開的短網址服務。使用者貼上長網址後取得短網址，任何人點擊短網址時會收到 HTTP 302 回應並跳轉至原網址。

## 功能需求

- 產生 7 碼短碼。
- 透過短網址跳轉至原網址。
- 支援自訂短碼（選配）。
- 支援設定過期時間。

## 非功能需求

請將下列數值填入 System Params：

| 參數 | 目標值 |
| --- | --- |
| DAU | 10,000,000 |
| 寫入 | 500 萬個新短網址／天 |
| 讀寫比 | 100:1（`readWriteRatio: 0.99`） |
| Peak QPS | 12,000 |
| 延遲目標 | p99 < 50ms |
| 可用性 | 99.99% |
| 資料保存 | 5 年 |

## 面試官追問

- 短碼如何產生才能避免碰撞？比較 hash、發號器與 base62 自增方案。
- Redirect 應使用 301 還是 302？為什麼？
- 資料庫應選 SQL 還是 NoSQL？
- 快取失效如何處理？

## 交卷補充

除了架構圖，請附上容量估算過程，以及至少一個關鍵 trade-off 的取捨理由。完整格式請參考[題庫首頁](./README.md#交卷方式)。
