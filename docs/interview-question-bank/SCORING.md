# 評分標準

每題滿分 100 分。

| 評分面向 | 配分 | 評估重點 |
| --- | ---: | --- |
| **需求釐清與容量估算** | 15 | 是否估算 QPS、儲存與頻寬；System Params 是否合理。 |
| **架構正確性與元件選型** | 25 | 元件是否齊全、職責是否清楚、連線方向與 protocol 是否正確，例如 gRPC 與 HTTP、同步與非同步。 |
| **資料儲存與一致性** | 20 | DB 選型理由、schema 概念、分片與讀寫分離、CAP 取捨。 |
| **擴展性與可用性** | 20 | SPOF、replicas、autoScaling、health check、快取策略與 fallback。 |
| **非同步與解耦** | 10 | MQ 是否用在適當位置，以及 DLQ、delivery guarantee 與削峰設計。 |
| **安全與可觀測性** | 10 | WAF（inline/L7）、認證、Logger 覆蓋率與 alerting。 |

## 評語分級

- 🔴 **面試會被打槍的致命問題**
- 🟡 **能過但不亮眼，補上會加分的項目**
- 🟢 **加分項與 senior 級追問**：面試官會直接追問，回答後再調整分數。

## 重要提醒

### 1. 不要為了清除所有 warning 而畫圖

畫布的 45 條規則屬於靜態 lint，可以找出 SPOF、缺少 WAF、MQ 未設定 DLQ 等問題，但無法判斷：

- 容量估算是否錯誤。
- Feed 的 push 或 pull 選型是否恰當。
- 庫存是否可能超賣。
- 分片鍵是否選錯。
- 資料模型設計是否合理。

真正的面試分數主要來自後者；人工評分會涵蓋靜態規則無法判斷的部分。

### 2. 不要只提交架構圖

交卷時應附上估算過程與取捨理由。面試官不只是在看圖，更重要的是理解你如何思考、如何比較方案，以及為什麼做出目前的選擇。

完整交卷格式請參考[題庫首頁](./README.md#交卷方式)。
