# Q4 — 電商限時秒殺

**難度：** 高難度
**建議時間：** 40 分鐘

## 情境

設計一個電商限時秒殺系統。單一商品只有 1,000 件，開賣瞬間會有 200 萬人同時搶購。

## 功能需求

- 顯示開賣倒數。
- 下單並扣除庫存。
- 串接第三方金流，透過非同步回調取得付款結果。
- 查詢訂單。

## 非功能需求

請將下列數值填入 System Params：

| 參數 | 目標值 |
| --- | --- |
| 尖峰 QPS | 500,000（開賣後 10 秒內） |
| 平均 QPS | 2,000 |
| 絕對要求 | 不可超賣 |
| 延遲目標 | p99 < 300ms |
| 可用性 | 99.95% |

## 特別要求

必須明確說明此系統的 CAP 取捨，以及該取捨如何支援「不可超賣」的要求。

## 面試官追問

- 庫存應放在 Redis 還是資料庫？兩邊如何對帳？
- 扣除庫存的原子性如何實現？
- 流量應在哪一層擋下？比較前端限流、WAF、API Gateway rate limit 與 MQ 削峰。
- 付款失敗後，庫存如何回補？如何避免重複回補？
- 你的 CAP 取捨是什麼？犧牲了什麼，又保住了什麼？

## 交卷補充

除了架構圖，請附上容量估算過程，以及至少一個關鍵 trade-off 的取捨理由。完整格式請參考[題庫首頁](./README.md#交卷方式)。
